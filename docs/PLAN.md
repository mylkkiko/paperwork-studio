## 2. Module notes (non-obvious logic)

### 2.1 Merge fields & rendering
- Delimiters `{{ }}`. Keys are dotted (`student.full_name`). docxtemplater is configured with a custom parser
  that looks up the **whole dotted key** in a flat map (`{"student.full_name": "..."}`), so we never depend on
  nested objects and the snapshot stays flat and easy to diff/audit.
- Field extraction uses docxtemplater's `InspectModule` after compiling the template, so fields split across
  Word runs (`{{stu` + `dent.full_name}}`) are reassembled exactly as at render time. Unknown keys → returned
  as `warnings` (template is still saved as draft) and **block publishing** until fixed or added to the dictionary.
- Values are formatted by dictionary `type`: `date` → `21 նոյեմբերի 2026 թ.`, `money` → `150 000 ֏`
  (non-breaking space as thousands separator), `number` → grouped digits, `text` → as-is.
- `{{signature.checkbox}}` is a system field: `☐  Ստորագրություն՝ ____________`. The recipient signs by hand next to
  it (see §12: signatures are paper-only; there is no re-rendered ☑ copy, the uploaded scan is the signed copy).

### 2.2 Generation pipeline (BullMQ job per batch)
1. Load published version + recipients from `CoreEngineClient`, apply precheck overrides and exclusions.
2. For each recipient (concurrency 4): allocate number → build flat values (core + shared + per-recipient manual)
   → save `dataSnapshot` → fill docx → Gotenberg → store PDF+DOCX → `progress++`.
3. ZIP (archiver) of all PDFs/DOCX, merged PDF (pdf-lib). Status `completed` / `failed`.
- Budget: 24 Gotenberg conversions ≈ 1–2 s each with concurrency 4 → well under the 2-minute target.

### 2.3 Clause splitting (V-1)
- Text from mammoth `extractRawText`, split into paragraphs.
- A paragraph starts a new clause if it matches `^(\d+(?:\.\d+)*)\.?\s` (e.g. `1.`, `2.1.`, `2.1.3`).
  Heading-styled paragraphs (Word `Heading 1–3`, detected via mammoth HTML `<h1..h3>`) without a number also
  start a clause, keyed by a slug of the heading text.
- Everything before the first clause is the `preamble` clause. Following non-numbered paragraphs are appended to
  the current clause (e.g. signature lines belong to the last clause).
- Merge field tags stay in the clause text (we compare templates, not filled documents).

### 2.4 Comparison (V-2/V-3) — *revised in Phase 1*
1. **Identical text** (any number): paired first. Required for renumbering: if 3.2 is removed and old 3.3 becomes
   3.2, matching by number first would wrongly pair old 3.2 with new 3.2. Ties prefer the same number.
2. **Same number**, if the texts are at least loosely similar (Dice ≥ 0.3); otherwise it's a replaced clause → removed + added.
3. **Best similarity** (Dice on word tokens ≥ 0.6), greedy, for clauses renumbered *and* edited.
- Paired → `unchanged` / `changed` (jsdiff `diffWordsWithSpace` spans), with `moved: true` when the number changed.
  Unpaired old → `removed`, unpaired new → `added`. Output is in new-document order with removed clauses in place.

### 2.5 Summary (V-4/V-5/V-6)
`SummaryGenerator` interface; `RuleBasedSummaryGenerator` emits i18n phrases:
- `added`: "Կետ 6.2-ն ավելացվել է" / "Clause 6.2 added"
- `removed`: "Clause 3.2 removed"
- `changed` with exactly one numeric/date/money token changed → specific phrase:
  "Clause 4.2: number changed from 10 to 5" (plus a unit word when the token is followed by a known unit like
  `օր`/`աշխատանքային օր` → "payment term changed from 10 to 5 days" style phrasing via i18n),
  money → "amount changed from X to Y", date → "date changed from X to Y".
- otherwise: "Clause 7.1 wording changed".
Stored in `TemplateVersion.changeSummary` (generated in the hub locale `hy`; the comparison JSON is stored too so
the UI can re-render the summary in `en`). Editable while draft; locked on publish.

### 2.6 Signing tokens (S-2)
- `crypto.randomBytes(32)` → base64url (43 chars) in the link only. DB stores `sha256(token)` hex.
- Lookup by hash (unique index); constant-time compare not needed because lookup is by hash equality.
- Expiry `SIGN_LINK_TTL_DAYS` (default 14) = the deadline to hand in the signed paper. One active request per
  document; resending creates a new one and invalidates older ones. The link is view-only (see §12): GET/PDF keep
  working after signing, declining and the deadline; decline is rejected after the deadline (410) or when final (409).

### 2.7 Reminders (S-5)
- Pure function `dueReminders(doc, sentReminders, now, scheduleDays=[2,5])` → which reminder offsets are due.
- A BullMQ repeatable job (hourly) evaluates documents with status `sent`/`viewed`, unexpired request, and
  sends the due ones; each send writes a `Reminder` row + audit entry. Clock injected for tests.

## 5. Risks and mitigations

| # | Risk | Mitigation |
| --- | --- | --- |
| R1 | **Armenian fonts in PDF.** The stock Gotenberg image may lack Armenian glyphs → tofu boxes; LibreOffice silently substitutes fonts. | Custom image `FROM gotenberg/gotenberg:8` that copies Noto Sans/Serif Armenian TTFs (bundled in repo, OFL) into `/usr/local/share/fonts` + `fc-cache`. Templates set `Noto Serif Armenian` explicitly. Phase 2 test extracts PDF text (pdfjs-dist) and asserts Armenian strings, and checks the PDF font list contains `NotoSerifArmenian`. |
| R2 | **☐ / ☑ glyphs** are not in Noto Armenian. | Add `fonts-dejavu` / Noto Sans Symbols 2 to the image so LibreOffice falls back; assert `☑` in extracted text of signed PDF. Fallback plan if it renders badly: render the box with a Wingdings-free approach (a bordered 1-char table cell) — will report if needed. |
| R3 | **Fields split across Word runs** when a human edits the .docx (spell-check, formatting) → `{{stu` `dent.name}}`. | docxtemplater compiles across runs; extraction uses its InspectModule, not regex on XML. Test fixture builds a .docx with a field deliberately split into 3 runs (different formatting). Also catch docxtemplater `MultiError` (e.g. unclosed tags) and return them as 422 with tag/context details. |
| R4 | **Clause splitting** on real Word files: auto-numbering is not in extracted text; `1)` / `1.1` without trailing dot; numbers inside sentences; dates like `21.11.2026` at paragraph start. | Literal numbering is the documented convention (seed templates follow it). Regex requires the number at paragraph start followed by whitespace and limits depth to 4 levels and each part to ≤ 3 digits, so dates don't match. Word auto-numbered lists are a documented limitation (not parsed from `numbering.xml`): such a document has no detectable numbers, so it is split by headings only, or becomes one preamble clause; the word diff still works. |
| R5 | Renumbered clauses falsely shown as remove+add. | Similarity pass after number matching (§2.4). Unit tests with a renumbered fixture. |
| R6 | Gotenberg throughput / timeouts for 24 docs. | Concurrency 4, retries with backoff (BullMQ), per-call timeout 60 s. Measured in Phase 1 report. |
| R7 | Document number uniqueness under concurrency. | Postgres sequence-like counter row per year updated in a transaction (`UPDATE ... RETURNING`), unique index on `Document.number`. |
| R8 | Immutability of published versions / signed docs. | Service-level guards + tests; files written once with content hash in path; no update endpoints for them. |
| R9 | Personal data leakage (passport) in lists. | List DTOs are explicit allow-lists; `dataSnapshot` is never returned from list endpoints; test asserts it. |
| R10 | Mixed-run `{{signature.checkbox}}` text replaced by multi-line content. | Use docxtemplater `linebreaks: true`; checkbox content is a single line anyway. |
| R11 | Time zones in dates/reminders. | Store UTC; format dates in `Asia/Yerevan` (config `APP_TIMEZONE`). |

## 6. Assumptions (please confirm or correct)

1. **Clause numbers are literal text** in templates (not Word auto-numbering). Uploading an auto-numbered
   document still works, but clause comparison degrades to paragraph similarity.
2. **Merge-field `source` gets a third value `system`** for `document.number`, `document.date` and
   `signature.checkbox` (filled by the app, not by Core Engine or the coordinator). The spec lists only
   `core | manual`; without `system` these would be misreported as "missing manual data" in the precheck.
3. **Manual fields are pack-level by default** (G-4 shared fields: `contract.date`, `contract.amount`, …).
   In the precheck the coordinator may override any value per recipient (G-3). `document.date` defaults to the
   generation date.
4. **`academy.*` fields come from `CoreEngineClient.getAcademyInfo()`** (stubbed), not from env config.
5. **Unknown fields** do not block saving a draft, but **do block publishing** (422 with the list).
6. **"~10 numbered clauses"**: the student agreement has 8 numbered sections and 13 numbered sub-clauses; each
   section heading is itself a clause (title-only). Summary lines mention sub-clauses by number.
7. The **v1 → v2 demo** does not renumber clauses (3.2 removed leaves a gap; 6.2 is new) so the expected result
   is unambiguous; renumbering is covered by a separate unit-test fixture.
8. **Change summary language**: stored in Armenian (`hy`); the UI can regenerate it in English from the stored
   comparison. Once the editor edits the summary, the edited text is what is published and emailed (S-6).
9. **Signer identity**: the signer is the document recipient; email comes from Core Engine. Staff and partner
   documents use the same flow.
10. **Document statuses**: `expired` is set by the reminders job (or on opening the link) when the latest request
    expires without a signature; resending a new link moves it back to `sent`. Since §12 a paper signature is still
    accepted after expiry (`expired` → `signed`).
11. **Coordinator can mark paper signature** on any non-signed, non-declined document (incl. `created`).
12. **"Signed an older version"** (S-6) = a document whose status is `signed` and whose template version is
    not the template's current published version.
13. `admin` passes every role check (has all permissions of `editor` and `coordinator`).
14. Seed `.docx` files are reproducible in **content**; bytes differ between runs because Word metadata
    contains a timestamp.
15. JWT access token only (8 h lifetime), no refresh token — the spec asks only for an access token.

## 7. Decisions made during Phase 1

Confirmed by the product owner after Phase 0: all assumptions in §6, plus
- **Auto-numbering warning**: a template with Word automatic numbering (`w:numPr`) and no typed clause numbers gets
  the upload warning `CLAUSES_NOT_DETECTED` ("Clauses not detected — convert numbering to plain text"); the draft is saved.
- **Renumbering test (Phase 2)**: fixture with 3.2 removed and old 3.3 → new 3.2 (same text) must be "unchanged, moved".
- Drawn-box fallback for ☐/☑ is acceptable if fonts fail (not needed, see below).

Changes vs. the plan:
- **Fonts (R1/R2)**: the stock Gotenberg 8.40.0 image already has Noto Armenian, but fallback was wrong (emoji font for
  digits, broken line layout around ☐/☑). Fixed with a fontconfig file (`docker/gotenberg/fonts.conf`) instead of
  bundling fonts, plus putting ☐/☑ in their own run with `DejaVu Sans` (`docx.service.ts › isolateSymbols`).
- **Field extraction** uses a recording parser during a dry render, not `InspectModule` (that pulls in lodash).
  Same split-run handling, verified with a `{{stu` + `dent.full` + `_name}}` fixture.
- **Reminder links**: tokens are stored only as hashes, so a reminder can't resend the original link. Each reminder
  issues an additional token with the same expiry; "send" issues a fresh token and revokes older ones.
- **S-6 resend**: a new batch per group from the current version; manual values (amount, dates) are carried over from
  the signed document, Core Engine data is re-read; emails go out automatically when the batch completes.
- `GenerationBatch` got `presetValues` and `sendOnComplete`; `Document` got `declinedAt`/`declineReason`;
  `TemplateVersion` got `warnings`, `comparison`, `comparedToId`; `SignatureRequest.revokedAt`; `DocumentCounter`.

## 9. Bugs found and fixed by the Phase 2 tests

| Bug | Fix |
| --- | --- |
| A failed PDF conversion stopped the batch, but the other parallel workers kept generating in the background (could race with the job's retry). | `mapLimit` stops taking new items on the first error and waits for in-flight work before failing. |
| Invalid typed values (e.g. "someday" as a date) were only detected inside the background job. | Precheck validates values per field type (`invalidValues`); creating the batch returns 422 `INVALID_VALUES`. |
| All recipients excluded gave a misleading `MISSING_DATA`. | 400 "All recipients are excluded". |
| A reminder recorded at exactly the resend instant counted towards the new send's schedule. | Only reminders strictly after the latest send count. |
| S-6 picked "the version the recipient signed" by creation time; with equal timestamps it could choose an older version. | Prefer the highest signed version number. |
| A replaced clause (same number, different text) was listed "added" before "removed". | Removed clauses are emitted before an added clause at the same position. |

## 10. Phase 3 (frontend) decisions

- **Next.js 15.5** (latest 15.x) rather than 16: stable App Router + next-intl integration; nothing in the spec needs 16.
- **shadcn/ui** components are written in the repo (`src/components/ui`, Radix + Tailwind + CVA), the way the shadcn
  CLI would generate them, instead of running the generator.
- **UI language from a cookie**, not the URL, so email links `/sign/<token>` work unchanged. Armenian by default.
- **Russian (ru)** added as a third UI language (product owner request). The backend got a `ru` dictionary too, so
  generated summaries, upload warnings, statuses and CSV/XLSX headers are available in Russian. Emails, documents and
  the stored (editable) change summary stay Armenian.
- **Demo logins** with one-click buttons on the login page when `NEXT_PUBLIC_APP_ENV` is not `production`
  (docker-compose builds with `test`).
- **Dates in Armenian UI** are formatted in code (browsers lack Armenian month data and print "2026 M11 22").
- **Mobile signing**: phones get an "Open document" button instead of an inline PDF frame (mobile browsers render
  an empty frame).
- **Dependency pin**: Next 15.5 and next-intl require different `@swc/helpers` versions; pinned to 0.5.17 via npm
  `overrides`, and the folder is added to the standalone trace (`outputFileTracingIncludes`).

## 11. Phase 4 and known limitations

Tests: backend 326 (Jest + Supertest), frontend 58 unit/component (Vitest + RTL + MSW), 8 E2E (Playwright, real stack),
including the product owner's additions (phone signing; hy → ru → en with no missing translations, verified to fail
when a key is removed).

Known limitations of this build:
- **Core Engine is a stub** (in-memory data); a real `HttpCoreEngineClient` is still to be written.
- **Files on local disk** (`StorageService` → S3 later); no virus scanning of uploaded scans.
- **Auth**: JWT access token only (8 h), kept in `localStorage`; no refresh tokens, password reset or login rate limiting.
  The public signing endpoints have no rate limiting either (tokens are 256-bit, so guessing is not practical).
- **Templates**: Word automatic numbering is not parsed (warning `CLAUSES_NOT_DETECTED`); clause matching uses word
  similarity thresholds (0.3 / 0.6) that may need tuning on real documents.
- **PDF rendering** depends on the fonts in the Gotenberg image; the .docx files use Noto Serif Armenian, which Word on
  Windows may not have installed (it substitutes a font).
- **Emails** are plain text and always Armenian; delivery is to Mailpit in this environment.
- **Phones** open the PDF in a new tab (no in-page renderer such as react-pdf).
- **Reminders** run hourly (configurable cron), so a "day 2" reminder can arrive up to an hour after the 48 h mark.
- **E2E** expires a link by updating Postgres directly (waiting 14 days is not practical).
- **Native date inputs** show the browser's date format, not the selected UI language.

## 12. Change request: paper-only signatures

A checkbox on a web page has no legal force for these documents; the handwritten signature on paper does.

New flow: email with link → recipient opens and reads the document (`viewed`) → prints it, signs by hand next to the ☐
box → hands it to the coordinator → coordinator uploads the scan → `signed`.

| Area | Change |
| --- | --- |
| Public link | `GET /api/sign/:token` and `/pdf` only deliver the document; `POST /api/sign/:token` was removed (404). Nothing on the public link can set `signed`. `POST …/decline` stays (before the deadline). |
| Signing | `signed` is set only by `POST /api/documents/:id/paper-signature`, scan (PDF/JPG/PNG) required. Allowed from created / sent / viewed / expired (late paper is accepted). |
| Deadline | `SIGN_LINK_TTL_DAYS` (14) = deadline to hand in the paper. sent/viewed after the deadline → `expired`; the link still shows the document with "deadline passed, contact your coordinator"; decline → 410. Signed/declined never expire. Send again → new 14-day period, old link replaced. |
| Reminders | Same schedule (day 2 and 5); stop once the scan is uploaded, the document is declined or expired. |
| Emails | First email, reminder and new version: review, print, sign by hand next to the box, hand it to your coordinator by the deadline (Armenian). |
| Documents | ☐ line unchanged. The "re-render with ☑" signed copy is removed; the scan is the signed copy. Migration `20261123120000_drop_signed_pdf_path` drops `Document.signedPdfPath`. |
